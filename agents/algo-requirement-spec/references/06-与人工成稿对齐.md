# 与人工成稿对齐

这份文档记录"智能体初稿"和"人工核对后的成稿"之间的差异，以及为对齐成稿而写进规则的做法。判断依据是同一条需求的两版文档：智能体按旧规则输出的 Markdown，和人工核对修改后的 PDF 成稿。

结论先给：人工改动集中在三件事——**把元信息和过程痕迹清干净、把可枚举内容改成结构化表达、把没有材料支撑的内容删掉**。格式、模块和字段并没有被推翻，固定模版保持不变，改的是每个小节里"写什么、写多细、用什么形态"。

## 一、人工实际改了哪些地方

### 格式

| 维度 | 智能体初稿 | 人工成稿 | 结论 |
|---|---|---|---|
| 正文来源锚点 | 几乎每条结论都挂 `[原型]` / `[评审会议录音]` | 正文没有任何锚点 | 锚点只用于内部核对，成稿允许不标；前提是前言写清材料来源 |
| 截图 | 输出相对路径图片链接 `./assets/xxx.png` | 用真实截图配一行说明 | 不写本地相对路径链接；没有可随文档交付的图时，用一行文字描述截图内容 |
| 前言 | 复述材料、写"业务口径以某材料为准""历史人工拆解：未提供" | 只留原始需求链接和密码 | 前言只写链接、密码、材料是否提供，不复述内容、不堆元信息 |
| 版本号与日期 | `1.0.0` / `2026-10-11` | `客户端V13.4.0` / `2026年10月10日` | 沿用材料里的版本命名和日期写法，不套用默认格式 |
| 变更人 | 留空 | 按模版默认或材料作者填写 | 变更人优先按材料/模版填，实在没有依据再留空 |
| 需求背景七个节点 | 多个节点留空 | 七个节点全部填上真实时间 | 优先把七个时间节点从材料里提取填满 |

### 内容

| 维度 | 智能体初稿 | 人工成稿 | 结论 |
|---|---|---|---|
| 规则取值 | 挤在一段话里 | 做成"项 / 取值与规则"表 | 固定取值集用表格 |
| 效果指标 | 与目标效果混写 | 单独做"指标 / 口径"表，另起一行写统计窗口 | 指标口径单列成表，统计窗口单独点明 |
| 算法实验 | 自行补了对比基线、通过标准、复测方式 | 只保留正向样本与负样本，各自下挂缩进分点 | 基线、通过标准、复测方式是可选内容，材料没给就不写，不自行补 |
| 模型 | 只写"由研发确定"，一个模型名都不提 | 材料里明确的名字照写（剪映AI-GenSongV4、Qwen系列模型），材料没给能力的写"模型待确认" | 已确认的模型/厂商名照写，未确认的写"模型待确认"，都不得编造 |
| 无效信息 | 出现 `[推断]`、待确认口径 | 全部删除 | 不写推断结论，不列待确认清单 |

### 模块与小节写法

| 小节 | 人工怎么组织 |
|---|---|
| 【新增功能】 | 先一段总述要建设什么，按路径用编号列出三条，再用一张"模块 / 路径 / 用户可选的来源 / 能力与限制 / 列表与展示 / 结果去向"对照表把差异并排说清；流程用编号；特殊情况逐条分点 |
| 【算法功能】·能力 | 按能力编号逐条列（音轨提取、AI 音乐生成、提示词润色），本版明确不做的能力单列一条并写原因 |
| 【算法功能】·效果 | 目标效果、成功示例、失败示例各自用分点写，不再揉成一段 |
| 【算法功能】·边界 | 能力边界与特殊情况分开，逐条分点，边界带原因 |
| 【算法功能】·流程 | 用流程树覆盖推荐、导入、AI 音乐三条路径和失败/取消分支，输入输出在树后用分点补充 |
| 【算法功能】·实验 | 只写正向样本与负样本，样本来源、覆盖场景用缩进分点 |
| 【后端需求】·能力 | 一句总述 + 按能力分点（曲库升级、列表归集、导入与上传承接、AI 音乐任务、内容合规） |
| 【后端需求】·前端配合 | "路径 / 前端负责 / 后端负责"三列表格，表格后一段收尾说明试听、空态、失败重试、允许离开页面等共性表现 |
| 【后端需求】·模型 | 按能力分点，能确定的写名字，不能确定的写"模型待确认" |
| 【后端需求】·特殊情况 | 逐条分点，每条给触发条件、处理方式和用户可见结果 |

### 写法

- 解释性内容（建设什么、能力总述、前端配合说明）用简洁段落，一条主线讲完。
- 并列、无先后的内容（能力边界、异常清单、特殊情况）逐条分点。
- 有先后或有优先级的（用户操作步骤、处理顺序）用编号。
- 多对象同维度对比、固定取值集、指标口径用表格。
- 端到端链路、分支和兜底用流程树。
- 不再把可枚举内容挤成一整段，也不碎成一堆一句话 bullet。

## 二、据此写进规则的做法

| 规则 | 落点 |
|---|---|
| 前言只写链接、密码、材料是否提供 | agent 前言小节、`02`、`03`、模版 |
| 版本号与日期沿用材料写法，变更人按模版/材料 | agent 版本信息小节、`02`、`03`、模版 |
| 需求背景七个节点优先提取填满 | agent 需求背景小节、`02` |
| 不写本地相对路径图片链接，改一行截图说明 | agent 功能入口小节、`02`、`03`、模版 |
| 新增功能用"总述 + 编号 + 路径对照表 + 流程 + 分点" | agent 新增功能小节、`02`、`05`、模版 |
| 算法能力按能力编号，含"本版不做"+原因 | agent 算法功能小节、`02`、模版 |
| 目标效果/成功/失败分点，规则与指标各自成表 | agent 算法功能小节、`02`、`05`、模版 |
| 能力边界与特殊情况分开分点 | agent 算法功能小节、`02` |
| 流程用流程树覆盖分支与兜底 | agent 算法功能小节、`05`、模版 |
| 算法实验只写正/负样本，基线、通过标准、复测为可选 | agent 算法实验小节、`02`、`04`、模版 |
| 后端能力一句总述 + 分点 | agent 后端需求小节、`02` |
| 前端配合用"路径 / 前端 / 后端"表 + 收尾段 | agent 后端需求小节、`05`、模版 |
| 已确认模型名照写，未确认写"模型待确认" | agent 不写什么小节、`02`、`03` |
| 锚点稀疏、成稿可为零，格式只允许两种 | agent 证据锚点小节、`03`、`04`、`scripts/check_output.py` |

## 三、没有改动、继续保留的

- 固定模版的章节、顺序和名称：前言、版本信息、变更日志、需求背景、需求范围、需求拆解，以及 `## 【功能入口】``## 【新增功能】``### 【算法功能】``## 【后端】``### 【后端需求】`。
- 只补模版规定的内容，不新增效果定义、测试验收、风险待确认、证据附录等独立章节。
- 产品与研发边界：字段名、类型、枚举、JSON/XML、错误码、接口协议、存储路径、服务拆分、模型架构和部署都留给研发。
- 不列待确认清单，材料没给的值留空。
- 不出现甲方、乙方之类称谓，统一用需求方。
