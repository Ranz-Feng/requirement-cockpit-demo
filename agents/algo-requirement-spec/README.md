# 算法需求拆解专家

面向 WorkBuddy 的单专家包。把**需求原型 PDF**、**需求评审录音转写**和**历史人工需求拆解文档**整理成一份固定模版的需求拆解文档，只补充模版规定的内容，交给架构师、算法和后端继续细化。

只站 AI 产品视角写“要什么”，不写“怎么做”。字段、接口、模型选型和研发实现均由研发补充。

## 专家信息

| 项目 | 配置 |
|---|---|
| 名称 | 算法需求拆解专家 / Algorithm Requirement Spec Expert |
| 职业 | 算法需求拆解专家 |
| 类型 | 单专家 agent（expertType: agent） |
| 分类 | 产品设计（01-ProductDesign） |
| 标签 | 算法需求拆解、大模型输出规则、后端与前端对齐 |
| 版本 | 1.5.0 |
| 外部依赖 | 无 MCP、无连接器；内置模板与参考文件 |

## 固定模版

输出只允许以下章节，不新增效果定义、测试验收、风险待确认、证据附录等独立章节：

```text
# <需求主题> 需求拆解
# 前言
# 版本信息
# 变更日志
# 需求背景
# 需求范围
## 【功能入口】
## 【新增功能】
# 需求拆解
## 【算法】
### 【算法功能】
## 【后端】
### 【后端需求】
```

效果口径、测试方向和风险分别写入“目标算法效果”“算法实验”“特殊情况处理”等既有小节。

## 可以做什么

- 三份材料齐备时，按固定模版产出需求拆解文档。
- 缺少评审录音、历史拆解或原型时，按降级路径继续，材料没给的位置留空，不列待确认清单。
- 补全算法能力、目标效果、规则边界、输入输出业务信息和算法实验。
- 补全后端建设内容、前端配合点、模型能力需求与特殊情况处理。
- 按内容形态选行文方式：解释性内容写段落，并列规则分点，有先后的流程编号或流程树，多对象同维度对比和固定取值做表格。
- 与人工核对后的成稿对齐：前言只留链接与密码，版本号沿用材料写法，可枚举内容用表格，锚点稀疏甚至不标，材料已明确的模型名照写、未明确的写"模型待确认"。
- 在固定模版内做局部修改，不改变章节结构。

## 行文形态

段落、分点、编号、表格和流程树按内容形态选，不按习惯选，也不靠篇幅平衡：

| 形态 | 用于 |
|---|---|
| 段落 | 背景、目标、总述、因果解释、单条结论 |
| 分点 | 并列枚举、规则清单、能力边界、异常清单 |
| 编号 | 操作步骤、流程环节、判断优先级 |
| 表格 | 多对象同维度对比、固定取值集、指标口径与验收含义 |
| 流程树或 Mermaid | 端到端链路、分支与兜底、异步多阶段 |

单个要点超过 2 到 3 行还在塞并列信息就拆开；解释性内容也不切成一堆一句话 bullet。细节见 `references/05-表达形态与结构选择.md`。

## 明确不做

不写字段名、字段类型、枚举、JSON/XML 结构、错误码、接口协议、存储路径、轮询机制、服务拆分、表结构、部署方案、模型选型和排期承诺。产品部分完成即可，文档是给研发继续补充的输入。

## 导入方式

### 方式一：本机市场目录注册

```bash
python3 install_agent.py
```

脚本把本包复制到 `~/.workbuddy/plugins/marketplaces/my-experts/plugins/algo-requirement-spec/`，并写入该市场的 `marketplace.json` 清单。完成后重启 WorkBuddy，在【专家中心】→【我的专家】选择“算法需求拆解专家”。

### 方式二：应用端创建

【专家·技能·连接器】→【专家】→【我的专家】→【创建专家】，把 `agents/algo-requirement-spec.md` 的角色与规则作为创建要求，并参照 `plugin.json` 补齐展示配置。

### 方式三：开放平台 ZIP

把本目录压缩为 `algo-requirement-spec.zip`，保留 `.codebuddy-plugin` 隐藏目录，上传到 WorkBuddy 开放平台解析与提交。

## 推荐提问

1. 这是需求原型 PDF、评审录音和历史需求拆解，请按固定模版出一版需求拆解文档。
2. 这次没有评审录音，只有原型和历史拆解，请照常产出并标出无法确认的口径。
3. 只补充【算法功能】和【后端需求】，不要新增测试、风险等独立章节，也不要写研发实现。

## 使用边界

本地校验不等于 WorkBuddy 线上解析与实际运行结果。文档生成能力取决于运行环境。包内示例均为虚构内容。
