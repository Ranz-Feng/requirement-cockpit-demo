# 需求范围

## 【功能入口】

配乐页新增“智能配乐”入口。用户从创作页进入配乐页后即可看到，入口与现有“推荐音乐”“导入音乐”并列排布。区别在于前两条路径提供已有音乐，智能配乐根据素材或文字描述生成新的背景音乐。原型已给出入口位置与按钮状态，入口截图随原型材料提供。`[原型]`

三条路径的差异如下：

| 路径 | 音乐来源 | 用户需要提供 | 结果去向 |
|---|---|---|---|
| 推荐音乐 | 平台曲库 | 无 | 选中后回填创作页 |
| 导入音乐 | 用户本地或云盘文件 | 一个音频文件 | 选中后回填创作页 |
| 智能配乐 | 按描述生成 | 素材或文字描述 | 试听后回填创作页 |

## 【新增功能】

- **需要建设什么**：建设基于素材或文字描述生成背景音乐的能力，并让生成结果能够播放、试听、选择并回填到创作页。推荐和导入路径继续保留，三条路径共享同一个选择结果。`[原型]`
- **流程简要说明**：用户进入配乐页后选择推荐、导入或智能生成，三条路径的走向如下。`[评审会议录音]`

  1. 用户提交素材或文字描述，页面进入等待状态。
  2. 系统受理后完成内容理解与音乐生成，生成过程不要求用户守在页面。
  3. 生成完成后结果出现在配乐页，用户可以试听并选用。
  4. 选用后返回创作页，该音频作为背景音乐生效。
  5. 失败时保留当前页面，用户可以重新提交或切换其他路径。

- **特殊情况处理**：
  - 空输入时提示补充描述或选择素材。
  - 文件不可读或超长时直接失败并保留原页面。
  - 生成超时、内容违规或上游不可用时保留可恢复入口。
  - 重复提交时避免生成多份无人使用的任务。
  - 错误码等具体技术定义由研发补充。

# 需求拆解

## 【算法】

### 【算法功能】

- **需要建设的算法功能**：需要建设素材音轨提取、文字与素材理解、背景音乐生成、生成内容审核四类能力。推荐检索与导入解析已有能力可复用，但生成结果的可用性判断属于本次新增范围。`[评审会议录音]`
- **目标算法效果、示例、规则预设、能力边界与特殊情况**：用户提交素材或文字后，系统应生成可播放、时长适合、风格与输入基本一致的背景音乐。成功示例是生成结果可直接作为视频配乐使用；失败示例包括无法播放、内容明显跑题、命中违规规则或长时间没有结果。生成质量、合规和稳定性都要纳入效果判断。`[评审会议录音]`

  已经确认的规则取值如下：

  | 规则项 | 取值 |
  |---|---|
  | 输入来源 | 用户素材，或用户文字描述 |
  | 音乐形态 | 纯音乐、人声歌曲 |
  | 时长 | 自动、30 秒、1 分钟、自定义区间 |
  | 歌词 | 自动生成，或用户填写 |

  能力边界与例外：

  - 只允许基于用户提供的素材和文字描述生成，不开放自由对话式编曲。
  - 不承诺专业作曲级质量。
  - 不支持多素材混合输入。
  - 素材无音轨或文件不可读时不产出结果。
  - 生成异常或超时时不产出结果。

  效果指标口径如下，均可按任务粒度计算：

  | 指标 | 口径 | 判定含义 |
  |---|---|---|
  | 生成成功率 | 成功数除以发起数 | 链路是否可用 |
  | 可播放率 | 可播放结果数除以完成数 | 结果是否可用 |
  | 风格相关性 | 人工抽检通过率 | 结果是否贴合输入 |
  | 生成时延 | 提交到结果可见，取分位值 | 等待是否可接受 |
  | 人工采纳率 | 选用数除以完成数 | 结果是否有业务价值 |

  基线与目标值材料未给出，本次只统一口径，由算法与研发评估后回填。

- **大致流程、输入输出字段**：输入分两类业务信息，一类是用户素材，另一类是文字描述与形态、时长等创作设定。处理上先完成音轨提取与内容理解，再生成音乐，经过内容审核后把可播放结果交给用户。输出为可播放、可试听的音频及其展示信息，以及用户可见的任务状态。返回时机按异步处理，用户提交后先得到一条任务记录，结果在回到页面刷新后可见。字段名、类型和结构由研发补充。`[原型]`

  端到端走向与兜底如下：

  ```text
  用户提交
    ├── 素材：音轨提取
    │     └── 无音轨或不可读 → 失败提示
    ├── 文字：内容理解
    ↓
  背景音乐生成
    ├── 生成异常或超时 → 失败提示，可重试
    ↓
  内容审核
    ├── 命中违规 → 不返回结果
    ↓
  可播放结果 → 用户试听 → 选用或放弃
  ```

- **算法实验**：实验目的是验证生成的背景音乐能否直接被当作视频配乐使用，同时验证异常输入是否被正常拦截。`[评审会议录音]`

  1. 正向样本：
   - 提取侧取真实素材，覆盖不同格式、大小与时长档位，包含有人声与纯音乐背景的样本。
   - 生成侧取典型提示词，覆盖纯音乐与人声歌曲、不同时长区间。
  2. 负样本：
   - 空输入、超长文本、无音轨素材、损坏或不可读文件。
   - 带明显违规意图的提示词。

## 【后端】

### 【后端需求】

- **需要建设的后端功能**：后端需要承接配乐任务、组织素材与文字输入、调用音轨提取和音乐生成能力、管理生成结果及失败回退，并把用户选用结果回填到创作页。范围到业务处理和结果去向为止，服务如何划分、数据如何组织由研发决定。`[原型]`
- **需要和前端配合的地方**：前端负责触发入口、展示生成阶段、播放与选择结果，并在失败时提供重试和返回入口；后端负责受理任务、给出明确终态、提供可展示结果和处理失败信息。用户离开页面再回来时，需要能知道任务是否仍在进行；生成结果完成后应在配乐页可见。`[评审会议录音]`

  各路径职责划分如下：

  | 路径 | 前端负责 | 后端负责 |
  |---|---|---|
  | 智能配乐 | 收集素材或描述、展示生成阶段、播放与选用 | 受理任务、维护状态、提供可展示音频与明确终态 |
  | 推荐与导入 | 展示曲库与文件列表、控制按钮可用态 | 返回检索与文件列表、回填选用结果 |
  | 失败路径 | 提示并保留重试与返回入口 | 返回失败原因并保留可重试状态 |

  状态名、接口与通信方式由研发补充。

- **调用什么模型**：本需求需要四类能力，产品只定义要完成的业务任务与约束，不指定具体模型与调用方式。
  - 模型待确认：素材理解能力，用于识别素材音轨与内容特征。
  - 模型待确认：文字理解能力，用于理解用户的配乐描述。
  - 模型待确认：音乐生成能力，用于产出可播放的背景音乐。
  - 模型待确认：内容审核能力，用于过滤违规内容。

  选型由算法与研发评估确定。
- **特殊情况处理**：
  - 输入为空时提示用户补充条件，不进入生成。
  - 文件不可读时直接失败并保留原页面。
  - 重复提交时避免生成多份无人使用的任务。
  - 超时或部分结果可用时给用户明确提示。
  - 内容违规时不返回违规结果。
  - 上游不可用时允许退回推荐音乐。
  - 所有失败都要有一个可继续操作的结果，不能让用户停留在无反馈状态。
