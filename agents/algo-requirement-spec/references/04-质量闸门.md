# 质量闸门与自检清单

交付前逐条检查。任一闸门不过，不交付。

## 闸门 1：结构完全匹配固定模版

- [ ] 标题后只有前言、版本信息、变更日志、需求背景、需求范围、需求拆解六个一级章节。
- [ ] 需求范围下只有【功能入口】【新增功能】。
- [ ] 需求拆解下只有【算法】【后端】。
- [ ] 【算法】下只有【算法功能】，【后端】下只有【后端需求】。
- [ ] 没有新增“效果定义”“测试与验收”“风险分析”“待确认清单”“证据附录”等独立章节。
- [ ] 没有多余的一级、二级或三级标题。

## 闸门 2：内容只填规定范围

- [ ] 前言只写原始需求文档、密码和本次材料是否提供，没有复述材料内容或堆元信息。
- [ ] 版本信息只写版本号与创建日期，版本命名与日期写法沿用材料。
- [ ] 变更日志只包含时间、版本号、变更人、主要变更内容。
- [ ] 需求背景保留七个时间节点，材料没有的值留空，没有推算。
- [ ] 功能入口写清位置、进入方式和与现有功能的区别，并处理入口截图。
- [ ] 功能入口没有指向本地相对路径的图片链接；没有可交付图片时用一行文字描述截图内容。
- [ ] 新增功能只写建设内容、流程说明、特殊情况处理。
- [ ] 算法功能只写建设能力、目标效果与边界、流程与输入输出、算法实验。
- [ ] 后端需求只写后端建设内容、前端配合点、模型或算法能力、特殊情况处理。

## 闸门 3：材料一致性

- [ ] 原型、录音、历史拆解在引言的输入概况里说明。
- [ ] 缺评审录音时，已写“未经最新评审确认”，受影响内容不作延伸。
- [ ] 缺历史拆解时不影响产出；历史内容没有被当作本次事实。
- [ ] 缺原型时，入口与界面内容没有编造，无法支撑的部分留空。
- [ ] PDF 无可提取文本时已注明 OCR，并提示数字与专有名词待人工核对。

## 闸门 4：证据可追溯

- [ ] 关键结论只使用 `[原型]` 或 `[评审会议录音]`；没有出现其他来源标记。
- [ ] 没有页码、时间戳、段落号、说话人和历史拆解锚点。
- [ ] 锚点稀疏，同一小节同一来源不重复堆叠；成稿版正文允许不标锚点，前提是前言写清材料来源。
- [ ] `[推断]` 没有进入目标效果、实验通过标准和风险等级。
- [ ] 抽查任意连续 10 条结论，都能回到材料（原型、评审录音或前言声明的历史拆解）。

## 闸门 5：产品与研发边界

- [ ] 没有字段名、字段类型、枚举、默认值、JSON/XML 结构。
- [ ] 没有错误码、接口协议、请求方法、状态机英文枚举和轮询机制。
- [ ] 没有服务拆分、表结构、存储路径、部署方案和代码逻辑。
- [ ] 没有自行指定或推荐模型；材料已明确的模型/厂商名照写，未明确的一律写"模型待确认"。
- [ ] 没有写模型架构、训练方式或调用方式。
- [ ] 模版中的“输入输出字段”“调用什么模型”等内容已写明由研发补充。
- [ ] 没有排期承诺、人力承诺和未经确认的上线日期。

## 闸门 6：算法与后端可用性

- [ ] 算法同学能判断建设哪些算法能力、效果如何判定、边界与特殊情况是什么。
- [ ] 算法实验包含正向样本与负样本；基线、通过标准与复测方式为可选，材料没给的不自行补。
- [ ] 后端同学能判断建设范围、结果去向和前后端功能责任。
- [ ] 特殊情况覆盖异常、超时、空结果、违规、重复提交、降级和上游不可用等。
- [ ] 风险在对应小节中直接给出处理方式，没有另开章节。

## 闸门 7：行文形态

- [ ] 段落、分点、编号、表格、流程图和内容形态对得上，不是清一色段落或清一色 bullet。
- [ ] 并列规则、能力边界、异常清单用了分点，没有挤进一整段。
- [ ] 有先后的步骤和优先级用了编号。
- [ ] 多对象同维度对比、固定取值集和指标口径用了表格。
- [ ] 新增功能有路径对照表，算法功能有"项 / 取值与规则"表和"指标 / 口径"表，后端需求有"路径 / 前端负责 / 后端负责"表；没有可对比内容时才省略。
- [ ] 端到端链路、分支和兜底有流程树或 Mermaid 表达走向。
- [ ] 表格单元格只放短结论，没有把长句塞进表格。
- [ ] 没有单个要点堆到 3 行以上还在塞并列信息。
- [ ] 没有碎成一堆一句话 bullet，解释性内容仍用段落承接。
- [ ] 没有 `< >` 占位符和“成稿提醒”残留。
- [ ] 没有编造日期、人员、指标与结论，也没有列出待确认、待补充或需澄清的问题清单。

## 自动自检脚本

包内 `scripts/check_output.py` 会检查固定章节、必需子标题、锚点格式、研发越界信号、可枚举内容是否挤成超长单行和占位符残留。锚点是可选追溯信息，脚本不会因为没有锚点而报错。

```bash
python3 scripts/check_output.py <输出文档.md>
```

退出码：`0` 全部通过；`2` 只有告警，可交付但需人工确认；`1` 有错误，需返工。

脚本通过不等于文档合格，以上人工闸门仍需逐条检查。
