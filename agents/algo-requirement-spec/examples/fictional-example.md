# 需求范围

## 【功能入口】

目录列表页新增"智能摘要"入口，用户在浏览目录时可直接触发摘要生成。入口与现有入口并列，区别是现有入口只能逐条点开查看，智能摘要无需点开即可获得条目要点。原型已给出按钮位置与状态，入口截图随原型材料提供。`[原型]`

## 【新增功能】

- **需要建设什么**：为目录条目生成三段式摘要，并在处理完成后展示结果，同时提供重新生成入口。`[原型]`
- **流程简要说明**：用户点击"智能摘要"后进入处理中状态，生成完成后展示摘要与"重新生成"入口；失败时展示重试提示，并保留当前页面。`[原型]`
- **特殊情况处理**：条目为空时提示用户不可生成；超长条目、生成超时、输出不完整或内容违规时统一落到失败态并允许重试；上游不可用时给出失败提示。错误码等具体技术定义由研发补充。

# 需求拆解

## 【算法】

### 【算法功能】

- **需要建设的算法功能**：为单条目录内容生成三段式摘要，输出语言与原文一致。`[原型]`
- **目标算法效果、示例、规则预设、能力边界与特殊情况**：用户无需点开即可把握条目要点。成功表现是摘要与原文相关、总长不超过 200 字、三段结构完整；失败表现包括摘要与原文无关、超长、结构缺失或多次生成结果明显矛盾。规则预设与长度上限以评审口径为准，能力边界以外或出现异常时一律落到失败态。`[评审会议录音]`
- **大致流程、输入输出字段**：输入是条目正文，输出是三段文本；生成异步进行，完成后可回取。输入输出的业务类别到此为止，字段名、类型、枚举和结构由研发补充。`[原型]`
- **算法实验**：用目录条目构造评测集，覆盖短条目、长条目、术语密集内容与空内容等负样本，观察生成可用率与人工采纳率，并与人工判断的基线对比。不通过时暂停放量并复盘。`[评审会议录音]`

## 【后端】

### 【后端需求】

- **需要建设的后端功能**：承接摘要生成任务、组织条目输入、调用摘要生成能力、管理结果与失败回退，并把结果回填到列表页展示。范围到业务处理和结果去向为止。`[原型]`
- **需要和前端配合的地方**：前端负责触发入口、展示处理中与成功/失败状态、提供重新生成；后端负责受理任务、给出明确终态、提供可展示结果与失败信息。用户看到处理中、成功、失败三个可见阶段，重试回到处理中。状态名和接口细节由研发补充。`[原型]`
- **调用什么模型**：需要具备长文本理解与摘要生成能力的模型或算法服务，满足长度控制与不编造原文事实的要求。具体模型与调用方式由研发确定。
- **特殊情况处理**：空条目直接失败并提示；超时、输出不可解析、内容违规或上游不可用时保留重试入口，不留无反馈状态。风险在本节内说明处理方式，不新增独立章节。`[评审会议录音]`

## 三、这个示例演示了什么

1. 只使用固定模版的章节，没有出现效果定义、测试验收、风险待确认、证据附录等独立章节。
2. 效果、测试方向和风险分别写进【算法功能】和【后端需求】里既有小节。
3. 材料没有给出的数值、日期与口径一律留空，不编造，也不列成待确认清单。
4. 正文只标 `[原型]` 或 `[评审会议录音]`，不带页码、时间戳与段落号；历史拆解只参考结构，不标锚点。
5. 只写"要建设成什么样"，没有写服务拆分、表结构、存储路径，也没有自定义字段、JSON 结构与错误码。
6. 解释性内容用简洁段落，分点只用于模版列出的并列项。
